# 官方 Android App 抓包操作手册（RUNBOOK）

> 目标：完整捕获 `mimo.sz`（官方 Mimo app）与 OsmoAction4 的 **BLE + WiFi** 通信全流程
> 环境已就绪：HCI 日志已开、PCAPdroid 已装、脚本已备（见 README.md）

---

## 开始前：喊我一句话

**开始操作前告诉我"开始抓包"**，我会：
- 启动后台 logcat 全量监控（main/system/events/crash → `captures/logcat-*.log`）
- 设置 `svc power stayon usb`（USB 供电时屏幕常亮，防止锁屏断连）

⚠️ 全程保持 USB 线连接，不要拔。

---

## 阶段 0：准备（约 2 分钟）

- [ ] 相机开机、电量充足、存储卡就绪
- [ ] PCAPdroid 检查：**目标应用 = mimo.sz**、**PCAP 文件保存位置 = Download**
- [ ] 手机蓝牙开、**WiFi 关闭**（阶段 A 需要纯蓝牙环境；连相机热点属于阶段 C）
- [ ] 点 PCAPdroid **▶ 开始** → 允许 VPN 权限（若弹"此网络无互联网"忽略即可）
- [ ] **从最近任务彻底划掉 mimo app**（保证冷启动）

## 阶段 A：冷启动 + BLE 扫描发现（纯蓝牙，无 WiFi）

- [ ] 打开 mimo app
- [ ] **停 10 秒**，等它扫描设备列表（不要点任何东西）
- [ ] 确认设备列表里出现 OsmoAction4

> 抓包关注：BLE 广播包、扫描响应、广播名/厂商数据格式

## 阶段 B：BLE 连接 + WiFi 凭据下发

- [x] 点击连接相机，进入连接流程，**停 5 秒**
- [ ] 观察是否出现"连接 WiFi / 配网"提示 —— **BLE 下发 WiFi SSID/密码就发生在这一步**
- [ ] 若 app 提示打开 WiFi，此时再**打开手机 WiFi**

> 抓包关注：GATT 服务发现、特征值写读、MTU 协商、加密配对

## 阶段 C：WiFi 连接 + 控制握手

- [ ] 允许 app 连接相机热点（Android 可能弹"此网络无法访问互联网，保持连接？"→ 点**保持**）
- [ ] 等 app 进入**预览页**，**静置 10 秒**（不要操作，抓纯握手+心跳流量）
- [ ] 确认手机连上 `OsmoAction4-**`

> 抓包关注：TCP/UDP 端口、协议版本协商、初始参数同步、主题订阅

## 阶段 D：核心功能操作（每步之间停 5 秒）

- [x] 1. 静置预览 **10 秒**（抓心跳/状态轮询节奏）
- [x] 2. 拍照 **1 张**（等它处理完）
- [x] 3. 录像 **开始 → 等 5 秒 → 停止**
- [x] 4. 切换拍照/录像模式来回 **1 次**
- [x] 5. 参数调整：**EV 档位切换 1 次、快门速度调 1 次、白平衡调 1 次、ISO 调 1 次**
- [ ] 6. 进"设备信息/固件版本"页，看一眼再返回
- [ ] 7. 进**相册/文件列表**页（触发文件元数据同步），浏览几秒后返回

> 抓包关注：每类指令的请求/响应格式、参数写入协议、文件列表协议

## 阶段 E：断开流程

- [ ] 在 app 内断开与相机的连接（或关闭相机电源），**停 10 秒**
- [ ] 观察断开顺序：WiFi 先断还是 BLE 先断

> 抓包关注：断开指令、连接清理顺序

## 阶段 F：停止抓包 + 拉取（手机插着 USB，回来告诉我"抓完了"）

1. PCAPdroid 点**停止** → 确认 pcap 已保存到 Download
2. 电脑运行：
   ```bash
   ./capture-scripts/pull-pcapdroid.sh    # 拉 WiFi pcap
   ./capture-scripts/pull-btsnoop.sh      # 拉 btsnoop（bugreport，需 1-3 分钟）
   ```
3. 我会停止 logcat 监控、恢复屏幕常亮设置，然后开始分析

## 风险提示

- **若官方 app 在 PCAPdroid VPN 开启时拒绝工作/连不上相机**：先停止 VPN，按阶段 A-E 抓**纯蓝牙轮**（btsnoop 不受 VPN 影响），然后单独告诉我，我们再想 WiFi 轮的替代方案
- 全程尽量**不切后台、不让手机锁屏**；如果中途 app 崩溃或断连，直接继续，异常本身就是有价值的数据
