# 相机发现与接入（discovery）

> 证据：docs/protocol/mimo-ios.pcap 有效会话 19:52:35–19:55:20；早期 19:51:4x–19:52:3x 为连接前的调试流量。

## 1. 网络形态

相机自身提供 Wi-Fi AP（热点），手机加入后：

| 角色 | IP | 说明 |
| --- | --- | --- |
| 相机 | `192.168.2.1` | 同时是 DHCP 服务器（UDP 67/68 正常交互，19:52:33 观察） |
| 手机 | `192.168.2.140` | DHCP 分配 |

相机 AP 内**无互联网**；连接期间手机的蜂窝/其他 Wi-Fi 流量照常（与本协议无关）。

## 2. 端口角色（已证实）

| 端口 | 传输 | 方向 | 角色 |
| --- | --- | --- | --- |
| **9004** | UDP | 双向 | **主通道**：实时预览流（相机→手机）+ 控制命令/订阅/ACK（手机→相机），见 control-channel.md / live-view.md |
| **7001** | TCP | 双向 | 辅助通道：连接期握手帧、秒级心跳（见 control-channel.md §2） |
| 6001 | TCP | 手机→相机 | 仅收到单包 SYN 探测（78B，从未完成连接），贯穿全捕包期每秒一次；另探测 `192.168.0.1:60000`。用途未定（服务发现扫描） |

## 3. App 的探测行为（观察）

连接建立前后，App 持续发出：
- TCP SYN 探测：网关 `192.168.2.1:6001`、`192.168.0.1:60000`（~1/s，整个会话未停止）；
- ICMP Echo：手机↔相机 ~2/s（连通性监测，payload ~142B）；
- mDNS 组播 224.0.0.251:5353（常规服务浏览，未见相机应答记录）。

**iOS 实现建议**：发现阶段无需复刻探测扫描——直接对网关（相机）9004/7001 发起会话即可；探测行为仅用于判断"相机是否在线"可用单次 UDP 9004 探测或 ICMP 替代。

## 4. 接入流程结论

1. 手机加入相机 AP（iOS 可用 `NEHotspotConfiguration` 辅助，或引导用户手动加入）；
2. DHCP 取得 192.168.2.x 地址，网关即相机；
3. 直接开始 UDP 9004 会话（控制命令即刻可用），TCP 7001 并行建立（辅助状态）；
4. 无需蓝牙配对（本次抓包全程未见 BLE 流量参与远程控制）。
